\section{Description}


This package fixes various colour leaks one encounters with
the environments from Donald Arseneau's package
\ctanpackage{framed}.  Typically, colour leaks occur if using
|\color| (at top level or whose scope involves a page break) inside the
environments, or more subtly also when using |\textcolor| with
an argument ending up being split at a page break.

This latter type of colour leak (or colour disappearance) is the
more challenging one as the fix requires modifications or
replacements not only of some of the \ctanpackage{framed}.sty
macros (such as its |\CustomFBox|, which \colorframed overwrites)
but also to some \LaTeX{} internals, as some environments of
\ctanpackage{framed}.sty rely on usage of |\fbox| or |\colorbox|.
Rather than overwriting internal \LaTeX{} macros such as
|\@frameb@x| or |\color@b@x|, \colorframed simply replaces |\fbox|
and |\colorbox| in the \ctanpackage{framed}.sty environments by
appropriate substitutes.

I am aware \ctanpackage{tcolorbox} package documentation explains at
least one colour issue which looks similar to those fixed
here in \ctanpackage{framed} context, and that the fix overthere uses
an extra colour stack, hence is not \XeLaTeX{} compatible
currently.

The problems are solved here without involving an extra
colour stack, hence the fixes work also with \XeLaTeX.

Since release |1.0| the environments are also usable in documents
producing tagged PDF, see section~\ref{sec:tagging}.

\colorframedTFconlabcolorcommand

whose default definition let it expands to nothing at all (the continuation label

Regarding the `framed' environment, \colorframed adds the
\begin{verbatim}
\colorframedbordercolorcommand
\end{verbatim}
which expands by default to |\normalcolor|.  It influences the colour of the
framing done by environment `framed', the original having no such
customizability.  Do not redefine it to do nothing, it always should set some
colour, else the borders may display colour loss after a page break.

For example
\begin{verbatim}
\setlength{\FrameRule}{5pt}
\setlength{\FrameSep}{9pt}
\renewcommand\colorframedbordercolorcommand{\color{gray!50}}
\end{verbatim}
configures the next usage of `framed'.

\setlength{\FrameRule}{5pt}
\setlength{\FrameSep}{9pt}
\renewcommand\colorframedbordercolorcommand{\color{gray!50}}
\begin{framed}
  This environment allows indeed customization of the border width
  and of the separation with contents, via |\FrameRule| and
  |\FrameSep|.

  The length |\FrameSep| influences also `oframed', `shaded', and `shaded*',
  but `snugshade' and `snugshade*' employ |\fboxsep| rather.

  |\FrameRule| influences both `framed' and `oframed'.
\end{framed}

\section{Summary of the customization interface}
\label{sec:summary}

This section lists the colours and the commands which matter for
customizing the environments.  What has a name starting with |\colorframed|
is provided by \colorframed, all the rest by \ctanpackage{framed}, whose
documentation (|texdoc framed|) is the reference for it.

\section{Tagged PDF}
\label{sec:tagging}

\begin{shaded}
\emph{The tagging support (the added code, the test files and tools of the
repository, and the present section) was written by Claude, the AI model of
Anthropic (Claude Fable 5.2) on 2026/11/12.}
\end{shaded}

Since release |1.0| the environments of \ctanpackage{framed}, as modified by
\colorframed, can be used in a document which activates the tagging of the PDF
via |\DocumentMetadata| (with |tagging=on|).  This was developed and tested
with pdf\LaTeX{} and \LuaLaTeX, using the \LaTeX{} release |2026-11-01| and
\ctanpackage{tagpdf} |1.0i| and |1.0j|.  Two of the test files of the repository were
also compiled with success using \XeLaTeX.

There is nothing to do on user side, and no new user command.  A document not
using |\DocumentMetadata| is not concerned at all: none of the code added for
tagging is executed, and its output is the same as if this code did not
exist.

Here is what happens in a tagged document:
\begin{itemize}[noitemsep,topsep=3pt,parsep=3pt]
\item Each environment is a |Sect| structure, which contains what the
  contents of the environment give when tagged as they would be without it.
  This is what \ctanpackage{tcolorbox} does for its boxes.  It applies to
  all environments, `leftbar' included.  (At release |1.0| no environment
  had a structure.)
\item With pdf\LaTeX{} a paragraph which \ctanpackage{framed} had split
  across two pages was wrongly tagged (its marked content was left open at the
  bottom of the first page and its continuation on the next page was not
  tagged at all).  This is fixed.  \LuaLaTeX{} had no such problem.
\item The title of a `titled-frame' (more generally, the title argument of
  |\TitleBarFrame| or of |\colorframedTitleBarFrame|) was not tagged.  It is
  now a |Caption| structure, the first child of the |Sect| of its frame,
  again as with \ctanpackage{tcolorbox}.  The title may contain mathematics
  or |\emph|.  (At release |1.0| it was a paragraph before those of the
  frame.)
\item The titles repeated after page breaks (those with |(cont)| appended)
  and the continuation labels are marked as artifacts.  This applies to the
  titles coming from |\MidFrameCommand| and |\LastFrameCommand|.
\item The rules and the coloured backgrounds drawn by the environments are
  marked as artifacts.  This is needed with pdf\LaTeX{} only, as \LuaLaTeX{}
  does it on its own for all material which is not tagged.
\end{itemize}

%\begin{footnotesize}
\begin{snugshade}
  \textbf{Technical notes.}
\begin{itemize}[noitemsep,topsep=3pt,parsep=3pt]
\item A title is typeset when the frame is drawn, hence after the contents of
  the frame.  To let it nevertheless come first in the structure tree, the
  package must know at the start of the environment that there will be a
  title, and it knows it only from the previous compilation.  So a document
  with titled frames needs one more compilation; as long as this information
  is missing the |Caption| comes after the contents of its frame and this
  warning is issued:
\begin{verbatim}
Package colorframed Warning: Titles of frames are not at their place in the
(colorframed)                structure tree. Rerun to get them right.
\end{verbatim}
\item All of the above also applies to an environment of your own if its
  |\FrameCommand| is built with |\CustomFBox| or |\colorframedcolorbox|, or
  with one of the two title bar macros.  If it is built with |\fbox| or
  |\fcolorbox| (which should be avoided anyhow, see the next section) then,
  with pdf\LaTeX, the rules they draw are not marked as artifacts.  This is
  not specific to frames: with pdf\LaTeX{} the \LaTeX{} kernel currently
  also leaves the rules of a |tabular| unmarked.
\item In a tagged document (and only there) \colorframed redefines the
  `leftbar' environment and these internal macros of
  \ctanpackage{framed}.sty:
\begin{verbatim}
\fb@put@frame, \fb@putboxa, \fb@sizeofframe, \TF@Title
\end{verbatim}
  and it adds code at the start of |\MakeFramed| and at the end of
  |\endMakeFramed| (for the |Sect| structure).
  The frame commands which \ctanpackage{framed} executes only to measure the
  frame are executed with tagging suspended.
\item Only public commands of \ctanpackage{tagpdf} are used.  One of them
  needed a workaround (the package creates a variable which
  \ctanpackage{tagpdf} should have created), see
  \href{https://github.com/latex3/tagpdf/issues/152}{tagpdf issue \#152}.
  This is fixed in \ctanpackage{tagpdf} |1.0j|; the workaround only acts
  with |1.0i|.
\item The repository contains test files (|test_tagging_*.tex|), a script
  compiling them with both engines and checking the tagging of the resulting
  PDFs, and a memo (|TAGGING_MEMO.md|) with more details.  The PDFs
  were not submitted to a PDF/UA validator.
\end{itemize}

\section{Technicalities, musings about future}

\begin{snugshade}
I first developed the analysis of the colour leaks/losses at page breaks with
\ctanpackage{framed} on occasion of some contributions I made to
the \href{https://github.com/sphinx-doc/sphinx}{Sphinx project} and I am
transferring here the gained knowledge.

The key thing is that the boxes handled by \ctanpackage{framed}.sty may
contain isolated colour push or colour pop.  We must make
sure an isolated colour push, if followed by colour changes,
is always followed by paired ones, and never by a colour pop
from a colour command originated "prior" and symmetrically that a sole
colour pop does not follow a yet unpaired colour push from some other
colour command related to the framing.

This means we can not ever use things such as |\fbox|, |\colorbox| or
|\fcolorbox| (whether or not \ctanpackage{xcolor} is loaded) as they will
cause colour pops after a possibly isolated colour push contained in the
(already boxed) contents which are fetched to them as arguments by
\ctanpackage{framed}.sty internals.  We must re-implement them otherwise.
This is what is done here, without touching the \LaTeX\ internal macros
themselves.

Some portion of the macro file is occupied with the
`titled-frame' environment of \ctanpackage{framed}.sty, which was broken by an
upstream LaTeX change related to |\smash|, and has obvious problems
apart from that.
Further "obvious problems" do exist for the other \ctanpackage{framed}.sty
environments but it is not the matter of this package to fix them.
Perhaps in future another package will be provided based upon the
work here and adding a completely new environment fixing the "obvious
problems" (some of them being simply lack of customizability).

The author has developed based upon usage of \ctanpackage{pict2e}
breakable boxes with round corners, background colour, optional
shadow (possibly inset), and other goodies and was planning on
incorporating this environment into the package at some time in future.
